# صورت‌جلسه پذیرش سرور Stage33

وضعیت: پذیرش کد تکمیل‌شونده است؛ نصب نسخهٔ Stage33 روی سرور هدف هنوز باید با بستهٔ immutable همین استیج اجرا شود.

## مبنای تأییدشده

لاگ اپراتور نصب Stage32 با source دقیق `b7306b323ea99baea1e6ebd8899de873fb62d4c7` بررسی شد. در آن اجرا:

- نصب و استقرار با `INSTALL_OK` و `DEPLOY_OK` پایان یافت.
- پیش از migration، پشتیبان خصوصی ساخته و اعتبارسنجی شد؛ مسیر ثبت‌شده `/etc/cryptosniper/backups/20261027-082613-1860315` بود.
- سرویس‌های وب، scheduler و workerهای مستقل فعال شدند و رسید heartbeat هفت صف ثبت شد.
- PostgreSQL، Redis، Nginx و مسیر HTTPS/login با پاسخ HTTP 200 تأیید شدند.
- timerهای پشتیبان رمزنگاری‌شده فعال بودند.

این شواهد فقط baseline سالم Stage32 است و به‌جای نصب Stage33 استفاده نمی‌شود.

## معیار بستن پذیرش Stage33

- installer منتشرشدهٔ Stage33 همان source و SHA256 درج‌شده در Release را نصب کند.
- migration `exchanges.0010_live_order_fee_receipt` اعمال و `check_deployment` موفق شود.
- تمام صف‌های اجباری heartbeat تازه داشته باشند و endpointهای live/ready موفق باشند.
- backup پیش از ارتقا و rollback نسخهٔ قبلی بدون حذف release قبلی قابل اجرا باشد.
- صفحه‌های مالک در عرض‌های 320، 390، 768 و 1440 بدون صفحه سفید یا اسکرول افقی بررسی شوند.
- snapshot موجودی یک حساب مجاز و زمان دریافت آن با صرافی مقایسه شود.

## موارد باز صریح

- نصب Stage33 روی VPS: منتظر اجرای اپراتور.
- مقایسه موجودی صرافی واقعی: نیازمند credential محدود و مجاز.
- Telegram و AI واقعی: نیازمند credential مجاز.
- فعال‌سازی معامله با پول واقعی: خارج از این صورت‌جلسه و نیازمند مجوز جداگانه است.

هیچ Secret، token، passphrase یا مقدار credential در این سند ثبت نمی‌شود.
