# قرارداد اجرای یک استیج کامل

این برنامه مستقیماً برای دستورهای «استیج N را یک‌باره با همه ورک‌ها بساز و در GitHub کامیت کن» تهیه شده است.

## ورودی هر اجرا

شماره استیج، برنامه repository و آخرین وضعیت واقعی HEAD. عبارت «بعدی» به اولین استیج تکمیل‌نشده اشاره دارد. اگر پیش‌نیاز ناقص است، باید علت آن روشن شود؛ استیج وابسته بی‌دلیل done نشود.

## روند الزامی

1. repository و شاخه پیش‌فرض، تغییرات موجود و سوابق تحویل را بررسی کن.
2. پنج ورک استیج را به‌عنوان یک درخواست واحد اجرا کن؛ برای رفتن از ورک ۱ به ۲ تا ۵ توقف یا تأیید جدا لازم نیست.
3. برای هر ورک کد، migration، قرارداد API، صفحه UI و Worker مربوط را به اندازه نیاز آن ورک بساز. وابستگی خارجی اعلام‌نشده را پنهان نکن.
4. آزمون واحد، integration و end-to-end متناسب با تغییر را اجرا کن. برای concurrency از PostgreSQL و Worker واقعی استفاده شود. آزمون mock به‌وضوح برچسب بخورد.
5. برای هر ورک کامیت فارسی با شناسه `SNN-WNN` ثبت کن. جمع‌بندی استیج، نتیجه آزمون و وضعیت برنامه نیز کامیت شود. تعداد معمول هر استیج پنج کامیت ورک و یک کامیت جمع‌بندی است؛ اصلاح‌های لازم می‌توانند کامیت بیشتری داشته باشند.
6. push و remote HEAD را بررسی کن. یک commit صرفاً محلی «ثبت در GitHub» محسوب نمی‌شود. با connector نیز ref باید به commit جدید منتقل و بررسی شود.
7. لینک commitها و شواهد تست را گزارش کن و در همان استیج توقف کن.

## تعریف وضعیت

| وضعیت | معنی |
|---|---|
| not_started | هیچ پیاده‌سازی این مرحله تأیید نشده |
| in_progress | کار آغاز شده ولی معیار تحویل کامل نیست |
| blocked | اطلاعات یا دسترسی ضروری بخش وابسته در دسترس نیست |
| partial | بخشی پیاده‌سازی/آزمایش شده، کل استیج کامل نیست |
| done | همه پنج ورک و checks مرتبط کامل، نتیجه ثبت و به GitHub ارسال شده |

قالب گزارش: هدف، نتیجه هر ورک، فایل‌های اصلی، migration، دستورها و نتیجه واقعی آزمون، mode paper/sandbox/live، محدودیت‌ها، مشخصات محیط بدون اسرار و commitهای ورک. کامیت جمع‌بندی نهایی نباید SHA خودش را در محتوای خودش ثبت کند؛ SHA آن پس از ارسال در پاسخ گزارش می‌شود.

## موارد نیازمند اطلاعات در زمان مربوط

- S03: نام صرافی‌های هدف و نوع حساب برای Adapter واقعی، در صورت لزوم حساب sandbox. emulator را می‌توان مستقل ساخت.
- S19: مشخصات و دسترسی همان هاست برای استقرار واقعی. توسعه محلی زودتر آغاز می‌شود.
- S21: API ID/hash، حساب مجاز Telethon، کانال‌های قابل دسترس، provider/model هوش مصنوعی و سیاست ارسال متن به آن. API keys، session و رمز ورود فقط در محیط امن وارد شوند.

این‌ها شرط گرفتن تأیید جدا برای هر ورک نیستند؛ فقط وابستگی‌های واقعی‌اند. نبود یک وابستگی با `blocked` و تفکیک تحویل مستقل گزارش شود.

## فرمان‌های آماده

> استیج ۱ CryptoSniper را با همه پنج ورک طبق برنامه مخزن کامل بساز، تست کن و با پیام‌های فارسی در GitHub کامیت و push کن.

> استیج بعد CryptoSniper را با همه ورک‌هایش کامل اجرا کن و پس از بررسی نتیجه در GitHub کامیت کن.

> استیج N را از آخرین ورک ناقص ادامه بده؛ همه ورک‌ها را تکمیل و نتیجه واقعی آزمون و لینک کامیت‌ها را گزارش کن.
