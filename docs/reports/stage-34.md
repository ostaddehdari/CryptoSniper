# Stage34 — گزارش پیشرفت

وضعیت استیج: `code-complete / external-acceptance-partial` — هر پنج ورک پیاده‌سازی شده‌اند؛ نصب Stage34 و پذیرش credential/پول واقعی خارج از ادعای این گزارش است.

## S34-W01 — نرخ‌های زنده و هدر

- ویجت قدیمی USDT/USD در React با BTC/USDT جایگزین شد.
- USDT/تومان مستقیماً از adapter عمومی نوبیتکس خوانده می‌شود؛ منبع و timestamp Provider همراه مقدار برمی‌گردد.
- React هر پنج ثانیه قیمت را تازه می‌کند و پس از بازگشت به tab بلافاصله refresh می‌شود.
- آخرین مقدار معتبر در قطع Provider حداکثر پنج دقیقه با وضعیت `stale` نگه داشته می‌شود؛ مقدار ناموجود با خط تیره و وضعیت «در دسترس نیست» نمایش داده می‌شود.
- دو Provider موازی خوانده می‌شوند و lock کش از هجوم همزمان درخواست‌ها جلوگیری می‌کند.
- ظاهر پایه React/Cornix حفظ شده و فقط stylesheet افزایشی Stage34 اضافه شده است.

## S34-W02 — معامله دستی و Fix Loss

- قیمت بازار انتخابی با درخواست مستقیم و محدود Provider هر پنج ثانیه تازه می‌شود و بازگشت به tab نیز refresh فوری دارد.
- ویجت قیمت به دکمه تبدیل شد؛ کلیک، Ask خرید یا Bid فروش تازه را در Entry سفارش Limit می‌نویسد و قیمت قدیمی/ناموجود قابل انتقال نیست.
- عبارت غلط `TP1 → Entry` به `SL → Entry پس از TP1` اصلاح شد.
- موجودی USDT قدیمی‌تر از ۳۰ ثانیه پیش از محاسبه مستقیماً از همان اتصال صرافی تازه می‌شود؛ شکست Provider با مقدار ساختگی جایگزین نمی‌شود.
- Fix Loss فاصله SL، کارمزد تخمینی ورود و خروج، Lot Step، Min Notional، سقف موجودی و اهرم مجاز را در بودجه ریسک محاسبه می‌کند.
- حجم ورود پیشنهادی بدون اعشار و خودکار در فرم قرار می‌گیرد؛ timestamp موجودی و ریسک محاسبه‌شده در UI دیده می‌شوند.
- سفارش این ورک همچنان Limit است؛ پشتیبانی واقعی Market بخشی از W05 و وابسته به قابلیت Provider است.
- پنج تست React، build تولید، Ruff، Django check، نبود migration جدید و دو تست PostgreSQL تازه‌سازی quote/balance پاس شدند.

## S34-W03 — اتصال پایدار صرافی‌ها

- ورودی «نام اتصال» از فرم و API حذف شد؛ نام از صرافی ساخته می‌شود و اتصال دوم همان صرافی شماره خودکار می‌گیرد.
- ساخت دوباره اتصال حذف‌شده همان رکورد غیرفعال را با credential جدید، وضعیت `pending` پاک و نام ثابت بازفعال می‌کند؛ خطای نام تکراری LBank حذف شد.
- شکست Provider یا صف دیگر داخل transaction rollback نمی‌شود؛ حساب از `pending` به `error` قابل مشاهده می‌رود و پیام اقدام مشخص بدون Secret ذخیره می‌شود.
- React تا پایان Sync حساب pending را هر ۲٫۵ ثانیه تازه می‌کند و خطای ثبت‌شده را کنار وضعیت API نشان می‌دهد.
- یک Sync اکنون مجوزها، بازارها، کارمزد حساب و snapshot موجودی را با هم تازه می‌کند؛ صفر USDT نیز snapshot معتبر است.
- قرارداد رسمی LBank برای مجوز، کارمزد، موجودی و دقت بازار و قرارداد Nobitex برای profile، fee، کیف پول و sandbox پوشش داده شدند.
- Ruff، شش تست React، build تولید، Django/schema، چهار تست PostgreSQL تازه این ورک و smoke مرورگر پاس شدند. artifact شواهد CI شماره `13542787908` است.

## S34-W04 — تحلیل سیگنال قابل سنجش

- Parser قواعد نسخهٔ `rules-v2` جفت‌ارز فشرده، فارسی/انگلیسی، اعداد فارسی، اعشار ابتدایی، بازه Entry، چند نماد و تعارض جهت را تشخیص می‌دهد.
- corpus مستقل `stage34-v2` دارای ۲۰ نمونه و ۱۴۰ assertion برای pair، side، Entry، SL، TP، مرور اجباری و منع اجرای مستقیم است؛ نتیجه محلی ۱۴۰/۱۴۰ است.
- completeness با حضور فیلدهای لازم و confidence استخراج با جریمهٔ ابهام گزارش می‌شود؛ هیچ‌کدام احتمال سود نیست.
- React متن اصلی، فیلدهای استخراج‌شده و هشدارها را نشان می‌دهد و فقط به صندوق بازبینی می‌رود؛ Parser/AI اجازهٔ ساخت مستقیم سفارش واقعی ندارد.

## S34-W05 — سفارش و مدیریت معامله صرافی

- فرم معامله نوع Limit/Market را ذخیره و در snapshot تغییرناپذیر برنامه ثبت می‌کند؛ درخواست تکراری با همان UUID سفارش دوم نمی‌سازد.
- Market فقط برای Providerهای صریحاً تأییدشده فعال است؛ Nobitex و adapter ناشناخته fail-closed و فقط Limit هستند.
- سفارش Market با `price=null` ارسال می‌شود؛ قیمت مرجع برای sizing/reservation نگه‌داری و درست پیش از ارسال، بهترین Ask/Bid دفتر سفارش حداکثر ۳۰ ثانیه‌ای دوباره بررسی می‌شود.
- migrationهای افزایشی نوع سفارش برنامه و قیمت مرجع سفارش را بدون حذف دادهٔ قبلی اضافه می‌کنند.
- sync معاملات خارجی، adoption صریح، inventory مبتنی بر fill تأییدشده، partial/unknown، TP/SL، trailing یکنواخت و restart همان موتور Stage31 است و در تست‌های تجمیعی باقی می‌ماند.
- هشت تست React، build production، Ruff، Django check و migration drift محلی پاس شدند؛ تست‌های وابسته به PostgreSQL در CI دقیق Release اجرا می‌شوند.

## مرز تحویل

هر دو کلید `LIVE_TRADING_ENABLED` و `LIVE_EXIT_MANAGEMENT_ENABLED` پس از نصب خاموش می‌مانند. هیچ credential واقعی یا سفارش پول واقعی در این تحویل استفاده نشده است. نصب Stage34 روی VPS و مقایسهٔ Provider به اقدام صریح اپراتور نیاز دارد.
