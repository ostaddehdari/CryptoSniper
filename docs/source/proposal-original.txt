در ادامه نسخه جامع پروپوزال را بر اساس تمام تصمیم‌های تثبیت‌شده CryptoSniper و با فرض **استقرار روی هاست پایتونی** تنظیم کرده‌ام. این متن می‌تواند مستقیماً مبنای قرارداد توسعه، طراحی دیتابیس و تبدیل به Stage/Work اجرایی قرار بگیرد. 


# پروپوزال جامع اجرایی سامانه CryptoSniper

## 1. عنوان پروژه

**CryptoSniper – سامانه هوشمند دریافت، پردازش، اجرا و مدیریت سیگنال‌های معاملات رمزارز**

نوع محصول: Web Application / PWA با رویکرد Mobile-First  
Backend اصلی: Python  
معماری پیشنهادی: Modular Monolith + Background Workers  
پایگاه داده اصلی: PostgreSQL  
سیستم Queue و Cache: Redis + Celery  
محیط استقرار: Python Hosting با پشتیبانی از پردازش‌های Background و ترجیحاً ASGI

---

# 2. تعریف پروژه

CryptoSniper یک سامانه حرفه‌ای برای دریافت، تحلیل، ثبت و اجرای سیگنال‌های معاملات ارز دیجیتال است.

هدف سیستم این است که کاربر بتواند سیگنال را از سه مسیر اصلی وارد سامانه کند:

1. **Manual Entry**
2. **Smart Paste**
3. **Automatic Signal Source – Telegram**

سپس سیستم، با توجه به تنظیمات کاربر، صرافی متصل، موجودی، وضعیت بازار، Entry، حد ضرر، اهداف سود، Trailing و سایر قوانین مدیریت سرمایه، معامله را ایجاد و مدیریت کند.

سامانه صرفاً «ثبت‌کننده سیگنال» نیست؛ بلکه یک **Trading Management Platform** خواهد بود که از زمان دریافت سیگنال تا بسته‌شدن معامله، گزارش عملکرد و اعلان‌های مرتبط، چرخه معامله را مدیریت می‌کند.

# 6. Smart Paste

کاربر می‌تواند متن کامل یک سیگنال را بدون پاک‌کردن توضیحات اضافی Paste کند.

برای مثال متن ممکن است شامل مواردی مانند:

Coin  
LONG  
ENTRY  
TARGET  
STOPLOSS  
Leverage  
توضیحات کانال  
هشدار مدیریت سرمایه  
Emoji  
متن تبلیغاتی

باشد.

Parser باید قسمت‌های مفید را استخراج کند.

خروجی استاندارد Smart Paste:

- یک Entry
- حداکثر سه Take Profit
- یک Stop Loss
- Coin/Pair
- Direction در صورت تشخیص
- Leverage در صورت وجود
- Source در صورت مشخص‌بودن

اگر بیش از سه TP در متن وجود داشته باشد، **فقط سه TP اول** برای اجرای معامله استفاده می‌شوند.

متن اصلی سیگنال نیز بدون حذف در دیتابیس ذخیره می‌شود تا امکان Audit و بررسی خطای Parser وجود داشته باشد.

# 7. Automatic Signal Source

منبع خودکار نسخه نخست:

**Telegram**

سیستم باید امکان تعریف Telegram Signal Source را داشته باشد.

هر Source دارای تنظیمات مستقلی خواهد بود.

برای هر منبع سه Mode اجرایی در نظر گرفته می‌شود:

### Manual

سیگنال دریافت و تحلیل می‌شود اما معامله به‌صورت خودکار ایجاد نمی‌شود.

### Semi-Auto

سیگنال دریافت و Parse شده و فرم آماده معامله برای تأیید کاربر نمایش داده می‌شود.

### Full-Auto

سیگنال دریافت، Parse، اعتبارسنجی و در صورت عبور از Ruleهای امنیتی و معاملاتی، معامله به‌صورت خودکار اجرا می‌شود.

# 12. Stop Loss

هر معامله یک Stop Loss اصلی خواهد داشت.

Stop Loss باید بتواند در طول معامله بر اثر Ruleهای مدیریت معامله تغییر کند.

تمام تغییرات SL باید در Event History ذخیره شوند.

برای مثال:

Move to Entry  
Move to TP1  
Trailing SL Update  
Manual SL Update

---

# 13. Trailing SL/TP

Trailing SL/TP باید برای هر معامله قابل فعال یا غیرفعال‌سازی باشد.

در Smart Paste تنظیمات Trailing به‌صورت پیش‌فرض فعال خواهند بود.

سیستم باید قیمت بازار را دنبال کرده و پس از فعال‌شدن Trigger مربوط، Stop را طبق الگوریتم تعریف‌شده جابه‌جا کند.

---

# 14. Percentage Trailing

قابلیت Percentage Trailing یکی از اجزای مهم مدیریت معامله است.

تنظیمات پیش‌فرض:

**Enabled = ON**

Trigger پیش‌فرض:

**TP1**

فاصله پیش‌فرض:

**1%**

وقتی Percentage Trailing فعال شود:

**تمام سفارش‌های فروش TP باقی‌مانده لغو می‌شوند.**

از آن لحظه کل حجم باقی‌مانده Position فقط توسط Trailing مدیریت خواهد شد.

برای مثال در یک معامله Long، اگر قیمت از TP3 نیز عبور کند، سیستم نباید Position را صرفاً به دلیل عبور از TP3 ببندد.

تا زمانی که Trailing Trigger اتفاق نیفتاده، معامله می‌تواند به رشد ادامه دهد.

# 16. Leverage

در Marketهایی که Leverage وجود دارد، سیستم باید:

- Max Leverage قابل استفاده را از Exchange دریافت کند.
- Leverage سیگنال را نمایش دهد.
- مقدار انتخابی کاربر را Validate کند.
- اجازه عبور از محدودیت Exchange را ندهد.

Leverage نباید به‌صورت Hard Code در سیستم ذخیره شود.

# 19. امنیت API صرافی

API Key و Secret یکی از حساس‌ترین داده‌های پروژه هستند.

قواعد امنیتی:

- API Key در Frontend ذخیره نشود.
- Secret هرگز به Frontend بازگردانده نشود.
- Secret در Log نوشته نشود.
- اطلاعات حساس در Database رمزنگاری شوند.
- Encryption Key خارج از Database نگهداری شود.
- API Key صرافی فقط مجوز لازم برای Trading داشته باشد.
- Withdrawal Permission نباید فعال باشد.
- امکان Test Connection هنگام افزودن Exchange وجود داشته باشد.
- آخرین زمان استفاده از API ثبت شود.
- امکان Disable فوری Exchange Connection فراهم باشد.

# 49. Parser Confidence

Confidence فقط میزان اطمینان فنی Parser به استخراج صحیح Signal است.

مثلاً:

Pair واضح: امتیاز بالا  
Entry مبهم: کاهش امتیاز  
SL پیدا نشده: کاهش امتیاز  
اعداد متناقض: کاهش امتیاز

در Full Auto می‌توان Threshold تعریف کرد.

مثلاً اگر Parser Confidence کمتر از حد تعیین‌شده باشد، Signal به جای اجرای مستقیم وارد Inbox شود.

**Frontend فقط رابط کنترل و نمایش باشد و هیچ عملیات حساس معاملاتی به بازبودن مرورگر وابسته نباشد.**

یا تلفن همراه خاموش شود،

پس از ثبت معتبر معامله، Monitoring و مدیریت TP، SL، Trailing و Alert باید توسط Backend و Workerهای سرور ادامه پیدا کند.

این اصل باید از اولین Stage توسعه رعایت شود.

# 73. نتیجه

CryptoSniper در معماری نهایی یک وب‌سایت ساده ثبت سیگنال نیست؛ بلکه یک **سامانه مدیریت چرخه کامل معامله** است.

معماری پیشنهادی عمداً به گونه‌ای طراحی شده که نسخه نخست روی زیرساخت Python اجرا شود، اما در آینده بتوان بدون بازنویسی اساسی سیستم:

کاربران بیشتر،

صرافی‌های بیشتر،

Telegram Sourceهای بیشتر،

Futures،

Perpetual،

AI Parser،

Mobile App

و قابلیت‌های پیشرفته‌تر Trading را به آن اضافه کرد.

مهم‌ترین تفکیک معماری نیز بین چهار بخش خواهد بود:

**Signal Engine → Trading Engine → Exchange Layer → Monitoring & Reporting**

و PostgreSQL به‌عنوان منبع دائمی حقیقت سیستم، Redis/Celery به‌عنوان زیرساخت پردازش Async و Django به‌عنوان هسته Application عمل خواهد کرد.


یک نکته مهم برای شروع ساخت: **قبل از Stage 01 باید مشخصات همان هاست پایتونی را بررسی کنیم**؛ چون اگر Persistent Process، Redis یا Worker نداشته باشد، معماری Deployment را باید از ابتدا متناسب با محدودیت هاست تنظیم کنیم، بدون اینکه قابلیت‌های CryptoSniper حذف شوند.
