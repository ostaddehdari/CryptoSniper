# استیج 22 — تکمیل Telegram، آرشیو کامل و سنجش تحقق سیگنال

شناسه: `S22` | وضعیت فعلی: `partial` | پیش‌نیاز: S21

## ورک‌ها

| شناسه | کار | تحویل مشخص | معیار بررسی |
|---|---|---|---|
| S22-W01 | اتصال و وریفای امن | ارسال/ارسال مجدد کد، انقضا، محدودیت تلاش، 2FA و session رمزنگاری‌شده | کد و password هرگز persist یا log نشوند |
| S22-W02 | آرشیو کامل | backfill از نخستین پیام، snapshot upper bound، cursor مستقل، pause/resume و FloodWait | restart/dedup پاس و automation تاریخی خاموش |
| S22-W03 | چندقالبی | قالب نسخه‌دار اولویت‌دار و دسته‌بندی پنج‌گانه پیام | noise معامله/Signal نسازد و markerها bounded باشند |
| S22-W04 | نتیجه تاریخی | OHLC عمومی، entry-first و سیاست ابهام TP/SL | هدف پیش از entry برد نیست؛ همان‌کندل ambiguous است |
| S22-W05 | تحویل | داشبورد، API خصوصی، job progress، تست، docs و installer | آمار resolved از ambiguous/no-data جدا و مالکیت enforce شود |

## مرز ایمنی

- واردسازی آرشیو همیشه با `allow_automation=false` انجام می‌شود و سفارش Paper یا Live ایجاد نمی‌کند.
- ارزیابی فعلی حداکثر ۳۰ روز داده عمومی Binance با interval یک‌ساعته را استفاده می‌کند. این داده مدرک قیمت همان صرافی مقصد نیست.
- نتیجه `ambiguous`، `no_data`، `open` و `not_triggered` در نرخ تحقق قطعی برد/باخت وارد نمی‌شود.
- credential، کد ورود و رمز دومرحله‌ای در گزارش، API یا HTML بازنمایش داده نمی‌شوند.

## تعریف پایان

کد و تست‌های مستقل هر پنج ورک حاضرند. اتصال واقعی Telegram، corpus کانال، محدودیت‌های FloodWait، CI exact-source، Release و نصب VPS به شواهد خارجی نیاز دارند؛ تا ثبت آنها وضعیت `partial` صادقانه است.
